# `.script` and other text scripts: parser and key tables

M2-R1 item 2. Sources: Cataclysm `parseLine` 0x00526120, `scriptSetStruct` 0x00526260, `scriptSet` 0x00526420 and the
key tables in `cataclysm.exe` `.data` (scanned with `tools/formats/script_probe.py --tables`, callbacks named from
`ghidra/exports/cataclysm_gog_r5/functions.csv`); HW1 `ORIG@ad1bb82:src/Game/statscript.h:20-45`,
`statscript.c:65,700-900` (`parseLine`, `findEntry`, `findStructEntry`, `scriptSetStruct`, `scriptSet`) and every
`scriptEntry`/`scriptStructEntry` table in `ORIG@ad1bb82:src/{Game,Win32,Ships}` (collected by regex over `{ "key",
callback`, `makeEntry(var, cb)`, `strEntry(var)` and the `make*TechEntry` macros). Data checked: all 951
`.script/.shp/.lod/.missphere/.mission/.level/.dist` files in `original/game_extracted/cataclysm/`.

## Summary

* **The text format and the parser are HW1's.** Same line grammar, same 650-byte line buffer (`fileLineRead(...,
  0x28a)`), same case-sensitive `strcmp` key lookup, same `setVarCB(directory, value, dataPtr)` dispatch, same
  `structureToFillIn + (offset1 - offset2)` for struct tables. **One parser change:** `parseLine` no longer cuts a line at
  `//` when the line contains `"http:"` (strings at 0x00897e04 / 0x0087bb18), so URLs survive in values.
* **105 key tables, 4,428 distinct keys** are compiled into the exe (141 name/callback tables before dropping front-end
  handler tables). **1,994 table keys do not occur in any HW1 table**; 1,342 of them are the new `LanguageStrings`
  entries for the new races, ships and techs, 652 are real tuning or loading keys. The new keys and their parsers are
  listed below, grouped by table and callback.
* **New Cataclysm-only tables:** beast-weapon statics (`cat_beastWeaponScriptTable` 0x00751698), research dependency
  table for the two new races (0x0088fb98: `SPRS*`/`MPRS*`/`MPRB*`, parsed by `cat_rsShipDependSetCB`,
  `cat_rsTechDependSetCB`, `cat_rsMPRBShipDependSetCB`), popup-menu and stats-screen textures (0x0088cb48,
  `cat_feOverlayIconTextureSetCB`), lens flares (0x008babb0, `cat_lf*`), keyboard bindings (0x008b6a48, `key`,
  `cat_kbKeySetCB`), ship names (0x008935a0, `ShipName`, `cat_shipNamesSetCB`), asteroid break pieces (0x00897930,
  `AsteroidBreakInfo`, `cat_scriptAsteroidPieceParse`), and a few one-key ship statics tables.
* **New keys in HW1-derived tables (the ones that change the data structures):** 29 ship-static fields
  (`supportUnits`, `providesSU`, `TimeShockedByEMP`, `EMP_Range`, `RamDamage`, `fowRadius`, `upgradeTimeModifier`,
  `externalBuild`, `beastAttackConvertTo`, ... see shipstatic.md), 8 gun keys (`StartUpgradeLevel`, `EndUpgradeLevel`,
  `GunSize`, `DamageMult`, `BulletSpeed2`, `FireTime2`, `BulletRange2`, `BulletLifeTime2`), mission/level keys
  `MeteorStorm`, `Slipgate`, `Mine`, `Fog`, `LensFlare`, the `WarpEnabled`/`LevelToWarpTo`/`Level`/`Tech` warp block,
  14 NIS commands (`repair`, `openSlipgate`, `fog`, `ebolts`, `beastEffect`, `subtitle`, ...), `useHomeworldLODSystem`
  in `.lod`, 156 tactics keys (per-ship `DodgeInfo[...]` for the new ships), 45 `tweak.script` keys (`twRepairRate[]`,
  `twSalvageDamageLimit[]`, processor auto-repair, crystal processing), 113 build caps (`Caps*`/`Capb*`/`Capk*`...), 41
  formation slots for the new ships, 31 new options in the config table (`utyOptionsList`).
* **HW1 keys that are gone (absent from the exe, not just from the tables): 968**, chiefly the HW1 race/ship names in
  strings (227), tactics (253), research (198), caps (82), dock tweaks (56, the whole `DockTweaks` table), Mothership
  special-door offsets (37), cloak/DDD/SalCap/P2 ship-specific tables. Data files still carry 641 key names the exe does
  not know (e.g. `explosionType` in 124 `.shp`, `DustCloud4..7` in 29 `.dist`); they are silently ignored, as in HW1.

## Layout (the "on-disk" side is text; the binary side is the key tables)

```text
file      := line*
line      := '[' ... | ']' ... | blank                       ; skipped by parseLine
           | ws* KEY (ws | '=')+ VALUE? (';' comment)?        ; '//' comment too, unless the line contains "http:"
KEY       := run of characters up to blank, tab or '='       ; matched case-sensitively (strcmp)
VALUE     := rest of line, trailing blanks stripped          ; may be empty; interpretation is the callback's
```

```c
typedef void (*setVarCback)(char *directory, char *value, void *dataToFillIn);

typedef struct scriptEntry {          /* 12 bytes, table ends with {NULL, NULL, 0} */
/*00*/ char        *name;
/*04*/ setVarCback  setVarCB;
/*08*/ void        *dataPtr;          /* absolute address of a global */
} scriptEntry;

typedef struct scriptStructEntry {    /* 16 bytes, table ends with {NULL, NULL, 0, 0} */
/*00*/ char        *name;
/*04*/ setVarCback  setVarCB;
/*08*/ udword       offset1;          /* address of the field in a template instance ...      */
/*0C*/ udword       offset2;          /* ... minus the template's base = offset in the struct */
} scriptStructEntry;
```

Both are unchanged from HW1 (statscript.h:20-33); Cataclysm's `scriptSetStruct` computes
`(info->offset1 - info->offset2) + structureToFillIn` exactly as statscript.c:813.

## Parser control flow

1. `scriptSet(dir, file, table)` / `scriptSetStruct(dir, file, table, struct)`: build `dir+file` (80-byte buffer),
   `fileOpen(name, FF_TextMode)`, loop `fileLineRead(fh, line, 650)` until `FR_EndOfFile` (-12).
2. `parseLine(line, &name, &value)`: skip `[`, `]`, empty; strip trailing blanks; cut at `;`; cut at `//` unless the line
   contains `http:` (new); skip leading blanks; split name at blank/tab/`=`; skip blanks; strip value.
3. Linear `strcmp` search of the table; on a hit copy the file name to `globalScriptFileName` (0x00c52da0) and call the
   callback. Unknown keys are ignored without a message.
4. Some files are parsed by hand-written loops instead of a table: `scriptSetGunStatics`, `scriptSetDockStatics`,
   `scriptSetNAVLightStatics` read `NUMBER_OF_GUNS`, `GUN`, `NUMBER_OF_DOCK_POINTS`, `NUMBER_OF_NAV_LIGHTS` blocks in
   `.shp`; `cat_scriptAsteroidBreakInfoLoad` reads `NUMBER_OF_ASTEROID_PIECES`. These keys are strings in the exe but
   in no table (listed under "Keys outside the tables").

## Open points

* The scan finds tables by shape (name pointer + code pointer). Hand-parsed formats (gun/dock/nav blocks, asteroid
  pieces, `.lod` LOD types via `lodTypeRead`, ETG `.ebg`, NIS bodies) have their own grammar beyond the key; only their
  keys are covered here. ETG function tables (0x0087a640.. single-entry tables, `etgFunctionTable`) belong to `.ebg`
  and were left out of the counts.
* Eleven callbacks are code addresses that Ghidra has no function for (`code_004a3f20` for `Mine`, `code_0057b8c0` for
  `LensFlare`, `code_00526060/70/80` for `DamageLo`/`DamageHi`/`BulletType`, `code_00504950` for the scenario
  `Description*` keys, ...): these are among the pointer-only code candidates of docs/binary-map.md R5.5.
* A few non-script handler tables pass the filter (`GoNowHyperspace`, `ShipsRemainingDraw`, single entries); harmless
  for key matching.
